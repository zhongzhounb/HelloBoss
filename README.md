# HelloBoss

在 BOSS 直聘按**你自己写的规则**筛选岗位并自动向 HR 打招呼，判定过程实时显示在一块本机大屏上。

**零依赖**：一个单文件的油猴（Tampermonkey）脚本，加一个只用 Node 内置模块的本地服务。

> 仓库目录名仍叫 `boss-auto-greeting`（旧名），对外的项目名统一是 **HelloBoss**。
> 目录与文件名没跟着改，是为了不让文档链接和启动脚本失效。

---

## 三个部件

| 文件 | 作用 |
|---|---|
| [`boss-greeting/zhipin-auto-greeting.user.js`](boss-greeting/zhipin-auto-greeting.user.js) | 油猴主脚本。翻岗位列表、读岗位信息、调本地服务拿判定、发招呼语、记流水 |
| [`boss-greeting/zhipin-devtools-unlock.user.js`](boss-greeting/zhipin-devtools-unlock.user.js) | 调试辅助。BOSS 页面有反调试逻辑，它让 DevTools 保持可用。**平时可以不装** |
| [`boss-greeting/server/`](boss-greeting/server/) | 本地服务（Node 22+，零依赖）。判定岗位、生成招呼语、托管大屏、存记录 |

## 快速开始

### 1. 装油猴脚本

浏览器装好 Tampermonkey / 油猴，然后**在大屏上点「安装油猴脚本」**（右上角那个链接，
脚本由本地服务发出来，不用去文件夹里找 `.user.js`）。

先起服务也没关系：脚本可以从仓库里那份
[`boss-greeting/zhipin-auto-greeting.user.js`](boss-greeting/zhipin-auto-greeting.user.js)
装，两条路装上去的是同一份脚本。

### 2. 起本地服务并打开大屏

不想碰命令行就用打包好的 `HelloBoss.exe`：**一个文件就是全部**，双击后它会打开大屏和
BOSS 直聘两个标签页。**判定服务默认停着**，到大屏右上角点「启动服务」才开始工作，
再点一次就停。

装好 Node 的话也可以从源码跑：

```bash
cd boss-greeting/server
npm start          # 需要 Node 22+；零依赖，不用 npm install
```

然后浏览器打开 <http://127.0.0.1:8787/dashboard>。

> **控制台跟着大屏页面走**：关掉大屏那个标签页 60 秒后，控制台和正在运行的判定服务
> 一起退出，不留后台进程。最小化、切到 BOSS 那页都不影响。建议把大屏标签页「固定」住
> （右键 → 固定），免得后台放久了被浏览器的睡眠标签页功能丢弃。
>
> 代价要清楚：控制台一关，油猴脚本就找不到判定服务了。判定是 fail-closed，
> 所以后果是**静默地一个岗位都不投**，而不是投错。

### 3. 在大屏上做三件事

大屏分成两页，顶栏的「① 设置 / ② 投递记录」切换：**① 设置**里填下面这几项，
**② 投递记录**里看每日投递量柱状图和每个岗位的判定流水。没配齐时顶栏会挂着一条红字，
两页都看得到。

| 配置 | 在哪配 | 不配的后果 |
|---|---|---|
| **AI 密钥** | 大屏「① 设置 → AI 接入」 | 判定全部跳过 —— 一个岗位都不投 |
| **投递规则** | 大屏「① 设置 → 打招呼判定」 | 同上 |
| **知识库** | 大屏「① 设置 → 打招呼样式 → 知识库」：把简历内容直接粘进去，点保存 | 同上 |

**大屏是唯一的配置入口** —— 没有配置文件要手改。改完保存立即生效，不用重启服务。

第一次打开时会问一句「要开启使用教学吗」—— 选「开启教学」，它会按顺序把上面这些
步骤逐一点到对应位置（装脚本 → 填三项 → 启动服务）。不想看就选「不用」，
以后从右上角「使用教学」随时能重新打开。

### 4. 确认脚本面板上的「问候语来源」是「AI 判定」

回到 BOSS 直聘页面，右侧脚本面板里的「打招呼配置 → 问候语来源」有三个选项：
**常用语 / 自定义文本 / AI 判定**。**默认就是「AI 判定」，不用改** —— 它是唯一会去问
本地服务的模式，上面那三项配置也只有在这个模式下才起作用。

另外两个模式发的是**你事先写好的固定文本**（BOSS 里存的常用语，或你自己敲的一段话），
每投一个岗位都一模一样。一字不变地连发几百遍是账号被判群发的头号原因，所以除非你很清楚
在做什么，不然别换。取不到常用语时脚本**不会**退回某句内置话术 —— 它会停下来告诉你。

---

## 投递规则就是一段自然语言

没有开关、没有阈值表单、没有配置文件 —— **规则整段就是你在大屏上写的那段话**：

```
月薪 20K 以上直接投；
否则公司规模 1000 人以上才投，创业小公司不投；
只投青岛、杭州、上海。
```

服务端不内置任何一条筛选逻辑，只负责把你的规则、知识库和岗位信息拼起来交给模型，
再把模型回的 `{"apply":true/false}` 解析成结论。想适配另一个人，换掉那段话就行。

不确定怎么写，点「① 设置 → 打招呼判定」里的 **`填入示例`** —— 它会填进一份多条件规则的样例，
照着改就行。（示例是编的，每个数字都得按你的情况改。）

---

## 为什么「没配就一个都不投」

自动发出去的招呼语**收不回来**，而漏投的岗位下次还能再投一遍。所以这一条是刻意做成
fail-closed 的：没配规则、没配密钥、没粘知识库，任何一项缺失都表现为「不投」，而不是
拿一套内置默认规则顶上。

理由很实际：这个仓库开源出去，别人是照着仓库里的默认状态跑的。一个「没配就直接开投」的
默认值，会让使用者在不知情的情况下按**别人的标准**投递。

同理，仓库里**不带任何默认知识库** —— 知识库空着就是「没有候选人资料」，一个岗位都不放行。
开源出去的默认状态不该替任何人认领一段经历。

---

## 招呼语由 AI 按岗位写

招呼语**不是固定句子**：每投一个岗位，模型都会拿知识库和 JD 现写一句 —— 对照 JD 提到的方向，
说你确实做过的那部分，结尾落到「感觉非常适合这份工作」。

**写到 HR 那个粒度，不是工程师那个粒度。** 读这句的人多半不懂技术：别堆技术名词，别点名他大概率
没听过的中小公司，说到「做过 Java 后端」「做过上位机客户端」这个方向就够了。

知识库是留给模型的**事实来源**，不是让它复述的内容 —— 所以它只会说知识库里真有的东西，
JD 里要而你没写过的，它会略过。

大屏「打招呼样式」里填的是**给 AI 的要求**，不是要发出去的文案。所以可以随便写细：

```
对照 JD 里提到的方向，说你确实做过的那部分。
不要点公司名，也不要说具体技术名词 —— 看这句的是 HR，不是工程师。
语气自信但别太推销，不要用感叹号。
```

**连发几百遍同一句招呼语，比发得多更容易出事** —— 这也是为什么这里不放固定文案。

同一条理由落实到脚本里，就是**不再有任何「兜底话术」**：取不到常用语、跨页状态丢了、
自定义文本空着，这三种情况以前都会退到一句内置问候语，现在一律停下并说明原因。
串起来看就明白了：那句兜底话术会绕过全部筛选（大屏上什么都没配也照发），
而它对每个岗位都一模一样。宁可漏投这几个岗位，也不能拿账号去赌。

另外**公司黑名单写在投递规则里**（大屏「① 设置 → 打招呼判定」的最后一行，`【黑名单】…`），
由模型连同其他规则一起判断。这么放是有意的：模型认得品牌名和工商全名的差异
（知道 `4399` 就是「四三九九网络股份有限公司」），而这正是字符串匹配做不好的地方。

代价是它**会漏判**。所以同一家的常见写法都写上（比如 `滴滴` 和 `嘀嘀` 都写），
实测只写 `滴滴` 拦不住「北京**嘀嘀**无限科技发展有限公司」。

## 项目结构

```
HelloBoss/
├── boss-greeting/
│   ├── zhipin-auto-greeting.user.js    油猴主脚本（也被打进 exe）
│   ├── zhipin-devtools-unlock.user.js  调试辅助（平时可不装）
│   ├── docs/                           设计文档
│   └── server/                         本地判定服务与大屏（Node，零依赖）
│       ├── src/                        服务源码
│       ├── launcher/                   打包与引导层
│       └── test/                       测试
└── README.md / AGENTS.md / LICENSE
```

开发模式下的运行期数据在 `server/data/`（含你的配置与知识库，gitignore 里，不会提交）；
exe 模式下在 `%LOCALAPPDATA%\HelloBoss\data`。两种模式都不会把数据传到别处。

---

## 打包成 exe（给没装 Node 的人）

`cd boss-greeting/server && node launcher/build.mjs` 产出 `dist/HelloBoss.exe` ——
**一个文件就是全部**，源码和油猴脚本都在它里面，发出去只需要发这一个 exe。
对方不用装 Node，双击后它会打开大屏和 BOSS 直聘两个 Edge 标签页。
判定服务默认不启动，由大屏右上角的按钮按需启停；关掉大屏 60 秒后控制台也会退出。

用户数据落在 `%LOCALAPPDATA%\HelloBoss\data`，不在 exe 旁边 —— 单文件之后
「整个文件夹拷走」这条保护没有了，数据跟着用户走比跟着文件走安全。

细节见 [boss-greeting/server/README.md](boss-greeting/server/README.md)。
