# HelloBoss Server —— 岗位判定服务与大屏

HelloBoss 的本地服务（源码在 `boss-greeting/` 目录下）。判定岗位值不值得投、生成招呼语、托管大屏、存判定流水。

- **零依赖**，只用 Node 内置模块。不需要 `npm install`。要求 Node 22+（用了内置的 `node --test` 与 `fetch`）。

```bash
npm start     # 默认 http://127.0.0.1:8787（单进程，判定也在这个进程里）
npm test      # 全部用例
```

## 两种启动方式

| 方式 | 行为 |
|---|---|
| `HelloBoss.exe` | 常驻一个**控制进程**：提供大屏、配置、记录与导出，并在 Edge 里打开大屏 + BOSS 两个标签页。**判定服务默认不启动**，由大屏右上角的「启动服务」按需拉起 / 停止 |
| `npm start` | 单进程：判定就在这个进程里，和以前一样。大屏的启停按钮会显示「服务运行中」并禁用 |

exe 模式下关掉大屏标签页，控制进程和正在运行的判定服务会一起退出；局域网模式开着时
不退出（那时服务是给整个局域网用的，不该由某一台设备的标签页决定生死）。

**没有单独的 `.cmd` / `.vbs` 脚本了。** 启动、重启服务、手机看大屏都在 exe 和大屏里完成：
- 重启判定服务 = 大屏右上角点「停止服务」再点「启动服务」。
- 手机看大屏 = 大屏右上角点「手机看大屏」，令牌与地址会显示在页面上。第一次开启时
  Windows 防火墙可能弹窗，选「允许」。

## 打包成 exe（给没装 Node 的人）

```bash
node launcher/build.mjs
```

产出 `dist/`，整个文件夹压成 zip 发出去：对方**不用装 Node**，解压后双击 `HelloBoss.exe`。

> 重新打包只替换代码与 exe，**不会清掉** `dist/data`、`dist/config/server.json`、`dist/resumes`
> 里的用户内容。要发给别人时，先手动删掉这些个人文件，别把简历、密钥或判定流水打进 zip。

exe 里只装了两样东西：**Node 运行时**和 `launcher/bootstrap.cjs` 这个引导层。`src/` 仍然
留在磁盘上，由引导层用 `import()` 去加载 —— 所以**改 `src/` 不用重新打包**，这个 exe 只在
Node 大版本变化时才需要重打。

`bootstrap.cjs` 里有三种身份（靠环境变量区分）：父进程只负责派生一个隐藏的控制进程并退出；
控制进程常驻并提供大屏；判定服务是控制进程拉起的子进程，跑在临时端口上。

几条不显然的地方：

- 引导层是 CommonJS。Node 22 的 SEA 只能跑 CJS 主脚本（ESM 主脚本要 Node 24 才有），
  但它能 `import()` 磁盘上的 ESM 源码 —— 上面那个「exe 与 src 分离」的结构正是靠这点成立的。
- 双击后黑窗会闪约 1.5 秒：exe 是控制台程序，父进程派生一个隐藏的自己就立刻退出，
  所以不会一直挂着一个黑窗。
- 控制进程已经在跑时再双击一次，会先请旧实例退出（判定服务一起停掉），再由新实例
  接管端口并打开网页 —— 每次双击拿到的都是一份干净的控制进程，不会悄悄复用跑了一整夜的旧服务。
- 判定服务用临时端口，不占固定端口，也就不会和别的软件撞车。它和控制进程之间用 stdin
  管道兜底：控制进程被强杀时管道断开，判定服务会跟着退出，不会变成孤儿。
- 注入会破坏 Node 官方签名（postject 会报 `The signature seems corrupted`，属预期），
  所以**从网上下到这个 exe 的人首次运行会被 SmartScreen 拦一下**（更多信息 → 仍要运行）。
  要消掉得买代码签名证书。
- 打包这一步要联网（`npx` 现下 `postject` 做注入）；打出来的 exe 运行时不依赖任何东西。
  仓库运行期仍是零依赖。
- `dist/` 只带 `resumes/example.txt`，不带你自己的简历与 `config/server.json`。


## 控制台跟着大屏页面走（关掉页面就停）

控制进程是隐藏着拉起来的，双击的这个人既看不见它、也没有正常手段关掉它。所以它自己退：
大屏页面会挂一条长连接（`GET /api/watch`），**这条连接在 = 有人看着**。
关掉大屏标签页 → 连接断 → 60 秒宽限后控制进程和判定服务一起退出
（宽限是留给刷新和断线重连的）。

- **最小化不影响**，切换到别的标签页也不影响 —— 那条连接不会被浏览器的后台限流掐掉，
  这也是它没用「页面定时打心跳」的原因：后台标签页的 `setInterval` 会被限流到约一分钟一次，
  会把正在干活的服务误杀。
- 想让它**一直在后台不退出**：用 `npm start` 手动起，或者在大屏上开启「手机看大屏」。
- **对局域网开放时不生效**：那时服务是给整个局域网用的，不该由某一个标签页决定生死
  （否则手机上随手关掉大屏，正在跑脚本的那台机器就没了判定服务）。
- 建议把大屏标签页**固定（右键 → 固定）**：Edge / Chrome 的「睡眠标签页」不会休眠固定标签，
  免得后台放久了被浏览器整个丢弃、连接跟着断。

代价要说清楚：控制进程一关，大屏和判定服务都没了。判定是 fail-closed，
所以后果是**静默地一个岗位都不投**，而不是投错 —— 大屏顶上就写着这条，别关它。

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 控制进程 / 单进程服务的监听端口 |
| `RESUME_SRC` | `<本目录>/resumes` | 简历目录。指向不存在的目录不会崩 —— 服务照常起，判定全部跳过并在大屏上提示 |
| `SERVER_CONFIG` | `<本目录>/config/server.json` | 服务配置文件的位置。给测试用来避开本机真实配置 |
| `BOSS_EXIT_WHEN_IDLE` | 未设 | `1` = 大屏页面关掉后进程自己退出。只有 `npm start` / 自动退出测试需要；exe 的控制进程默认就会这么做 |
| `BOSS_IDLE_GRACE_MS` | `60000` | 上面那条的宽限期。给测试用，正常不用改 |
| `HELLOBOSS_NO_BROWSER` | 未设 | `1` = 控制进程不打开浏览器。给开发 / 冒烟测试用 |

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | `{ ok, profiles, cache, aiConfigured }`。`profiles` 每次现读 resumes/，用户放进简历后警告条会自己消失 |
| POST | `/evaluate` | 判定一个岗位。`{ job: {...} }` → `{ apply, reason, greeting, meta }`。判定服务没启动时控制进程回 503 并说明原因 |
| GET | `/dashboard` | 大屏页面 |
| GET | `/api/service` | 判定服务的状态：`{ managed, running, state, port, pid, startedAt }` |
| POST | `/api/service/start` | 启动判定服务（exe 模式才有；命令行模式回 503） |
| POST | `/api/service/stop` | 停止判定服务 |
| GET | `/api/lan` | 手机访问状态：`{ managed, enabled, token, urls }` |
| POST | `/api/lan` | `{ enabled: true/false }` 开关局域网监听，必要时自动生成令牌并写回 `config/server.json` |
| GET | `/api/watch` | 大屏挂着的一条事件流（SSE）。它只是「有人在看」的信号，不推内容 —— 表格走 `/api/records` 轮询 |
| GET | `/api/records?since=<seq>` | 增量流水 + 统计 + 每日分组 + 当前判定服务状态 |
| GET / POST | `/api/settings` | 读 / 改配置。POST 会同时清空判定缓存（配置变了旧结论就过期了），并通知后台判定服务也清掉 |
| POST | `/api/cache/clear` | 内部接口：清判定缓存。控制进程在保存配置后调用它 |
| POST | `/api/ai/test` | 拿传进来的（或已存的）端点/密钥/模型实际打一次上游，给大屏的「测试连通」按钮用。探测结果一律回 200，看 `ok` 字段，另回 `format`（这次按哪种格式打的）；**不落盘、响应体不含密钥** |
| GET | `/api/export.csv` | 全量流水导出为 CSV（带 BOM，Excel 打开中文不乱码） |
| POST | `/report` | 追加一条流水。`runId` 与 `at` 由服务端补 |

## 配置分三处，各有各的归口

| 文件 | 改法 | 内容 |
|---|---|---|
| `data/settings.json` | **在大屏上改** | 判定规则（含公司黑名单）、招呼语样式（一段给 AI 的要求）、AI 端点/密钥/模型。运行时数据，不进 git |
| `config/keywords.json` | 手改，需重启 | 选简历版本用的关键词权重表 |
| `config/server.json` | **在大屏上开关**（也可手改） | 局域网开关与访问令牌。缺文件 = 只听本机、无鉴权。大屏开关会即时重绑监听并写回这个文件 |

`config/server.example.json` 是 `server.json` 的形状示例。

## AI 接入

支持两种上游格式，**按端点地址自动识别** —— 端点的路径以 `/chat/completions` 结尾就走
OpenAI 格式，否则走 Anthropic Messages 格式。不额外配格式，填端点、密钥、模型三样即可。

| 端点路径 | 格式 | 鉴权 | 默认值 |
|---|---|---|---|
| `/messages` 结尾 | Anthropic Messages | `x-api-key` + `anthropic-version` | `https://api.anthropic.com/v1/messages` |
| `/chat/completions` 结尾 | OpenAI chat/completions | `Authorization: Bearer` | —— |

Anthropic 官方、各类 Claude 中转（one-api / new-api / LiteLLM / CC Switch 之类）走第一种；
OpenAI 官方与绝大多数 OpenAI 兼容网关、以及**中转上按 OpenAI 格式挂出来的 DeepSeek / Qwen
等模型**走第二种。有些中转按模型分格式（同一个站上 `claude-*` 走 `/messages`、别的模型只走
`/chat/completions`），那就照着那个模型支持的路径填。

认不出路径时退回 Anthropic —— 那是加第二种格式之前唯一支持的那种，已有配置不受影响。
OpenAI 的 `/responses` 是第三种形状，**刻意不支持**。

面板上的「测试连通」会拿你当前填的端点/密钥/模型真打一次上游，当场告诉你能不能通 ——
不用先保存，密钥框留空就用已经存好的那把。它还会回一句「按哪种格式打的」，
所以填了个看不出格式的中转时能当场看明白。填错了会直接把上游的原话摆出来
（`接口返回 HTTP 400(按 OpenAI chat/completions 格式请求)` 之类），而不是笼统一句「失败」。

### 密钥不出网

大屏可以用令牌对局域网开放，所以响应体里**永远不含明文密钥**：

- `GET /api/settings` 返回的 `aiKey` 恒为空串，另给 `hasAiKey` 与 `aiKeyHint`（末四位）供显示。
- 空串同时是「本次未修改密钥」的哨兵 —— 大屏的密钥框不回填，用户改完规则顺手保存时那一栏是空的，
  若把空串当清空，保存规则就会悄悄废掉密钥。真要清空走 `clearAiKey`。
- 密钥只存在 `data/settings.json`（已 gitignore），不会随流水上报。

### 超时预算是一条严格递减的链

脚本侧等 45 秒 > 服务端最坏 42 秒（判定 30 + 生成 12）。每层必须小于上一层，
否则脚本先断开而服务端还在跑，日志会对不上。

底层是推理模型，推理过程与答案**共用** `max_tokens` 预算。预算被推理吃光时会返回
**HTTP 200 + 空 content 数组** —— 状态码正常、结构合法、只有内容是空的，极易被当成成功。
所以首轮用小预算保速度，只在快速失败时放大预算重试。

## 招呼语：AI 按岗位写，样式是一段给它的要求

每判定为「投」之后，模型拿简历事实 + 岗位 + JD 写一句招呼语：

- **写到 HR 那个粒度**，不是工程师那个粒度。读这句的人多半不懂技术：
  别堆技术名词（「CompletableFuture 异步化」他看不懂也不关心），别点名他大概率没听过的中小公司
  （除非是知名大厂），说到「做过 Java 后端」「做过上位机客户端」这个方向就够了。
- **对照 JD 挑重点，但只说自己确实做过的**。可以用 JD 的措辞，简历里没有的一律略过 ——
  JD 是用来挑重点的，不是用来编造的依据。
- 大屏「打招呼样式」里那段文字是**给模型的要求**，进 system prompt，**不逐字发出**。
  所以可以随便写多写细：「没有对得上的经历时怎么自荐」「语气别太推销」「不要用感叹号」。
- 只有一处硬兜底：生成不可用时发 `buildTemplateGreeting` 的模板句，并在 `meta.greetingFallback`
  里标出来（大屏看得到）。判定已经通过，不该因为一句措辞丢掉一个合适的岗位。

**为什么简历只当事实来源、不当复述内容**：早先那条「点名公司名 + 对上的技术点」的要求，
产出过「飞之辰实习做过采购寻源平台后端，用 CompletableFuture 做详情接口异步化」——
中小公司的名字 HR 没听过，技术名词他也不关心，一整句读完什么都没记住。
所以简历继续喂给模型（否则它会按 JD 编造你没做过的事），但只作为**事实来源**，不作为**复述内容**。

**为什么不做成「固定句子 + 随机挑一条」**：写得再好也跟具体岗位无关，而一字不变地连发几百遍
是账号被判成群发的头号原因。改成 prompt 之后，「匹配不上时怎么自荐」也能写成一句要求，
由模型每次换着说法表达 —— 自由度更高，也不会退化成复读。

> 想在匹配不上时发某句固定的话，直接写进样式里也行，但**要写成方向而不是原句**：
> 写死一句话，模型很可能一字不差地重复它，那正是要避免的模式。

模型看到的简历事实由 `buildResumeFacts` 拼装。它**不按固定槽位取字段**：`.txt` 的
「单位 | 时间 | 备注」把角色放在 `position`，而 `.typ` 宏格式把角色放在 `mid`、时间放在
`rule`（见 `resumeParser`）—— 按槽位取必然漏掉其中一种，而漏掉的正好是「实习岗位是什么」
这种最该让模型看见的信息。

各部分有字数上限（见 `RESUME_PROMPT_LIMITS`），**别调大**：招呼语预算只有 12 秒，而它受
脚本侧 45 秒超时链约束（见上文「超时预算」），塞爆提示词换来的只有「写出来又慢又泛」。


## 安全模型

- **默认只听回环地址**，不开鉴权。克隆下来不配任何东西就能跑。
- 开了局域网（`config/server.json` 里 `lan: true`）则**必须配令牌**，否则拒绝启动 ——
  那关系到把岗位记录连同写接口交给整个同网段。
- 令牌可以走 `Authorization: Bearer`，也可以走 cookie（手机浏览器只能走 cookie，
  页面里的 `fetch` 与「导出 CSV」的链接都带不了自定义请求头）。
- **回环地址豁免令牌**，所以本机浏览器与油猴脚本不用改。
- 写配置的接口额外做**跨站写入防护**：浏览器跨站发起的请求一定带 `Origin`，
  比对 host 即可挡住拿着 cookie 的跨站表单提交。不带 `Origin` 的一律放行（curl 与油猴脚本都不带）。
