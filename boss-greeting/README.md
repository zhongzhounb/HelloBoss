# HelloBoss —— 自动打招呼

在 BOSS 直聘按**你自己写的规则**筛选岗位并自动向 HR 打招呼，判定过程实时显示在一块本机大屏上。

## 三个部件

| 文件 | 作用 |
|---|---|
| `zhipin-auto-greeting.user.js` | 油猴主脚本。翻岗位列表、读岗位信息、调本地服务拿判定、发招呼语、记流水 |
| `zhipin-devtools-unlock.user.js` | 调试辅助脚本。BOSS 页面有反调试逻辑，它让 DevTools 保持可用。**平时可以不装** |
| `server/` | 本地服务（Node，零依赖）。判定岗位、生成招呼语、托管大屏、存记录 |

## 怎么装

### 1. 油猴脚本

浏览器装好 Tampermonkey / 油猴，然后**在大屏上点右上角的「安装油猴脚本」** —— 脚本由本地服务
发出来，不用去文件夹里找文件。（要用 DevTools 调试的话再装上 `zhipin-devtools-unlock.user.js`。）

还没起服务也可以，从仓库里那份 `zhipin-auto-greeting.user.js` 装，两条路是同一份脚本。

### 2. 本地服务

**推荐用打包好的 `HelloBoss.exe`**（在 `dist/` 里）：它**一个文件就是全部**，双击后会在 Edge 里
打开大屏和 BOSS 直聘两个标签页，全程不用碰命令行。**判定服务默认停着**，到大屏右上角点
「启动服务」才开始判定，再点一次就停。

> **控制台跟着大屏页面走**：关掉大屏那个标签页 60 秒后，控制台和正在运行的判定服务
> 一起退出，不留后台进程。最小化、切到 BOSS 那页都不影响。建议把大屏标签页「固定」住
> （右键 → 固定），免得后台放久了被浏览器的睡眠标签页功能丢弃。

代价要清楚：控制台一关，油猴脚本就找不到判定服务了。判定是 fail-closed，
所以后果是**静默地一个岗位都不投**，而不是投错。

有 Node 22 以上、想直接跑源码（零依赖，不用 `npm install`）：

```bash
cd server
npm start
```

然后浏览器打开 <http://127.0.0.1:8787/dashboard>。这种是单进程模式：判定就在这个进程里，
大屏上的启停按钮会显示「服务运行中」并禁用。

## 起来之后必须做的三件事

大屏顶部会有一条红色提示条，只要下面任何一项没做，它就会告诉你后果：

| 配置 | 在哪配 | 不配的后果 |
|---|---|---|
| **AI 密钥** | 大屏「① 设置 → AI 接入」 | 判定全部跳过 —— 一个岗位都不投 |
| **投递规则** | 大屏「① 设置 → 打招呼判定」 | 同上 |
| **知识库** | 大屏「① 设置 → 打招呼样式 → 知识库」：把简历内容直接粘进去并保存 | 同上 |

### 脚本面板上的「问候语来源」保持「AI 判定」

BOSS 页面右侧脚本面板里，「打招呼配置 → 问候语来源」有三个选项：**常用语 / 自定义文本 /
AI 判定**。**默认就是「AI 判定」，不用改** —— 只有它会去问本地服务，上面那张表里的三项
配置也只在它下面才起作用。

另外两个模式发的是事先写死的固定文本，每投一个岗位都一模一样。**一字不变地连发几百遍是账号
被判群发的头号原因**，这正是这个项目去掉「固定招呼语」的原因，所以别轻易换过去。

顺带说明当前的行为边界：取不到常用语、跨页状态丢失、自定义文本空着 —— 这三种情况**都不会**
再退到某句内置话术，而是停下并说明原因。宁可漏投，也不把同一句话发给所有人。

### 投递规则就是一段自然语言

没有开关、没有阈值表单、没有配置文件 —— **规则整段就是你在大屏上写的那段话**：

```
月薪 20K 以上直接投；
否则公司规模 1000 人以上才投，创业小公司不投；
只投青岛、杭州、上海。
```

服务端不内置任何一条筛选逻辑，只负责把你的规则、知识库和岗位信息拼起来交给模型，
再把模型回的 `{"apply":true/false}` 解析成结论。想适配另一个人，换掉那段话就行。

### 知识库

没有文件要放、没有格式要背：把简历内容**直接粘进**大屏「① 设置 → 打招呼样式」下面的
「知识库」框里，点保存就行。判定和招呼语都只按这段文字写。

一段普通的简历文本就可以，比如：

```
姓名: 张三，示例大学计算机技术硕士（2024.09 -- 2027.06）。
实习: 示例科技有限公司 后端开发实习生（2025.06 -- 2025.09），
      独立完成若干 REST 接口的设计与实现。
项目: 某分布式卡牌对战系统，全栈独立开发。
技能: JavaScript、Python、C++、SQL
```

**留空就等于没有候选人资料**，服务会一个岗位都不投 —— 这是刻意的 fail-closed：
自动发出去的招呼语收不回来，而模型不该在没有事实来源的时候替你认领任何经历。

知识库存在 `data/settings.json`（开发模式在 `server/data/`，exe 模式在
`%LOCALAPPDATA%\HelloBoss\data`），该文件不进 git，也不会离开本机。

## 为什么「没配就一个都不投」

自动发出去的招呼语**收不回来**，漏投的岗位下次还能再投一遍。所以这里刻意做成 fail-closed：
规则、密钥、知识库任何一项缺失，都表现为「不投」，而不是拿一套内置默认规则顶上。

理由很实际：这个仓库开源出去，别人是照着仓库里的默认状态跑的。一个「没配就直接开投」的
默认值，会让使用者在不知情的情况下按**别人的标准**投递。

## 大屏

打开后分成两页，顶栏的「① 设置 / ② 投递记录」按钮切换：

- **① 设置**（默认打开这一页）：打招呼判定（规则）、打招呼样式（一段给 AI 的要求，不逐字发出）
  以及它下面的知识库（直接粘简历）、AI 接入配置（可点「测试连通」当场验证端点/密钥能不能用）
- **② 投递记录**（左右两栏）：左边每日投递量柱状图，右边判定流水 —— 每个岗位的判定结果、
  实际是否发出、理由与话术；可导出 CSV。窄屏会折回成上下两段
- **右上角**：「启动服务 / 停止服务」；红条警告在标题栏，两页都看得到

没配规则 / 没填知识库时，顶栏那条红字会一直挂着 —— 那两项不配齐，读不回记录也属正常。
切到「② 投递记录」后页面会记住，下次刷新直接打开那一页。

**大屏是唯一的配置入口。** 改完保存立即生效，不用重启服务（判定缓存会同时清掉）。

> 注意：改 `server/src/` 下的代码则需要重启服务 / 重新双击 exe，Node 不会热加载。
> 改知识库或规则不用重启 —— 保存后下一个岗位就按新的来。

> 大屏只在本机打开（127.0.0.1）。早期版本的「手机看大屏」已经去掉。

## 目录结构

```
boss-greeting/
├── zhipin-auto-greeting.user.js
├── zhipin-devtools-unlock.user.js
├── docs/                     设计文档
└── server/
    ├── src/                  服务源码（判定 / 大屏 / 记录）
    ├── data/                 开发模式下的运行期数据：岗位记录、设置、日志（不进 git）
    ├── test/                 全部用例
    └── launcher/             打包成 HelloBoss.exe：引导层与资源清单
```
