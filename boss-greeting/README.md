# HelloBoss —— 自动打招呼

在 BOSS 直聘按**你自己写的规则**筛选岗位并自动向 HR 打招呼，判定过程实时显示在一块本机大屏上。

## 三个部件

| 文件 | 作用 |
|---|---|
| `zhipin-auto-greeting.user.js` | 油猴主脚本。翻岗位列表、读岗位信息、调本地服务拿判定、发招呼语、记流水 |
| `zhipin-devtools-unlock.user.js` | 调试辅助脚本。BOSS 页面有反调试逻辑，它让 DevTools 保持可用。**平时可以不装** |
| `server/` | 本地服务（Node，零依赖）。判定岗位、生成招呼语、托管大屏、存记录 |

## 怎么装

### 1. 油猴脚本

浏览器装好 Tampermonkey / 油猴，把 `zhipin-auto-greeting.user.js` 拖进去安装。
（要用 DevTools 调试的话再装上 `zhipin-devtools-unlock.user.js`。）

### 2. 本地服务

Windows 上**双击 `server/打开大屏.vbs` 就行** —— 它会先把服务隐藏着拉起来，再在 Edge 里
开好大屏和 BOSS 直聘两个标签页，全程不用碰命令行。需要 Node 22 以上（零依赖，不用 `npm install`）。

> **服务跟着大屏页面走**：关掉大屏那个标签页 60 秒后，服务自己退出，不留后台进程。
> 最小化、切到 BOSS 那页都不影响。建议把大屏标签页「固定」住（右键 → 固定），
> 免得后台放久了被浏览器的睡眠标签页功能丢弃。

代价要清楚：大屏一关，油猴脚本就找不到判定服务了。判定是 fail-closed，
所以后果是**静默地一个岗位都不投**，而不是投错。

其他系统、或者想让它一直在后台跑（关掉页面也不退）：

```bash
cd server
npm start
```

然后浏览器打开 <http://127.0.0.1:8787/dashboard>。

## 起来之后必须做的三件事

大屏顶部会有一条红色提示条，只要下面任何一项没做，它就会告诉你后果：

| 配置 | 在哪配 | 不配的后果 |
|---|---|---|
| **AI 密钥** | 大屏「AI 接入」面板 | 判定全部跳过 —— 一个岗位都不投 |
| **投递规则** | 大屏「打招呼判定」面板 | 同上 |
| **简历** | 把简历（`.txt`）放进 `server/resumes/`（别用 `example.txt` 这个名字，它会被跳过） | 同上 |

### 投递规则就是一段自然语言

没有开关、没有阈值表单、没有配置文件 —— **规则整段就是你在大屏上写的那段话**：

```
月薪 20K 以上直接投；
否则公司规模 1000 人以上才投，创业小公司不投；
只投青岛、杭州、上海。
```

服务端不内置任何一条筛选逻辑，只负责把你的规则、简历摘要和岗位信息拼起来交给模型，
再把模型回的 `{"apply":true/false}` 解析成结论。想适配另一个人，换掉那段话就行。

### 简历

`server/resumes/` 里带了一份模板 `example.txt`，是纯文本，照抄着改就行：

```
姓名: 张三

[教育经历]
示例大学 | 2024.09 -- 2027.06 | 硕士 · 计算机技术

[实践经历]
示例科技有限公司 | 2025.06 -- 2025.09 | 后端开发实习生
- 接口开发 | 独立完成若干 REST 接口的设计与实现。

[专业技能]
- 语言 | JavaScript、Python、C++、SQL
```

只有四样东西：`姓名:` 一行；`[章节名]`（认教育经历 / 实践经历 / 项目经历 / 专业技能）；
`单位 | 时间 | 备注` 的条目；`- 标签 | 内容` 的描述或技能。空行随便加，
以 `//` 开头的整行是注释。服务只做文本提取，**不需要装 typst、也不渲染 PDF**。

**注意 `example.txt` 这个名字会被跳过** —— 它是给人看格式的，不会被当成你的简历
（否则没配东西的人会拿里面的「张三/示例大学」去投递）。换成你自己的：复制一份、
改成别的文件名（比如 `java.txt`）放回去即可；想按技术方向放几个不同版本也行，
服务会按岗位 JD 的关键词自动挑最贴的那个（关键词表在 `server/config/keywords.json`）。

旧的 `.typ` 宏格式（`#init` / `#resume_section` / …）仍然照读，已经写好的 `.typ` 简历不用改。

该目录下除示例外的文件默认不进 git（见 `server/resumes/.gitignore`）—— 简历是个人信息。

## 为什么「没配就一个都不投」

自动发出去的招呼语**收不回来**，漏投的岗位下次还能再投一遍。所以这里刻意做成 fail-closed：
规则、密钥、简历任何一项缺失，都表现为「不投」，而不是拿一套内置默认规则顶上。

理由很实际：这个仓库开源出去，别人是照着仓库里的默认状态跑的。一个「没配就直接开投」的
默认值，会让使用者在不知情的情况下按**别人的标准**投递。

## 大屏

打开后能看到：

- **上半屏**：打招呼判定（规则）、打招呼样式（招呼语样例，配了就随机挑一条原样发出）、
  每日投递量柱状图、AI 接入配置（可点「测试连通」当场验证端点/密钥能不能用）
- **下半屏**：判定流水 —— 每个岗位的判定结果、实际是否发出、理由与话术；可导出 CSV

**大屏是唯一的配置入口。** 改完保存立即生效，不用重启服务（判定缓存会同时清掉）。

> 注意：改 `server/src/` 下的代码则需要重启服务，Node 不会热加载。
> Windows 上双击 `server/重启服务.cmd`。

## 手机上看大屏

```bash
# 管理员权限运行
server/手机看大屏-开启.cmd     # 生成访问令牌 + 放行防火墙 8787 端口，并打印手机可访问的地址
server/手机看大屏-关闭.cmd     # 用完撤掉防火墙规则
```

开启后服务会绑到局域网地址，**非本机来源必须带令牌**（本机浏览器与油猴脚本豁免）。
令牌存在 `server/config/server.json`，该文件不进 git。

## 目录结构

```
boss-greeting/
├── zhipin-auto-greeting.user.js
├── zhipin-devtools-unlock.user.js
├── docs/                     设计文档
└── server/
    ├── src/                  服务源码（判定 / 大屏 / 记录 / 简历解析）
    ├── config/               关键词表；server.json 为运行期生成（局域网令牌）
    ├── resumes/              简历目录，带一份示例
    ├── data/                 运行期数据：岗位记录、设置、日志（不进 git）
    ├── test/                 195 个用例
    └── *.cmd / *.vbs         Windows 一键启动器
```
